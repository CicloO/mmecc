# AdvancedMotionBlur P1 参数手册

## 参数在哪里改

| 想改什么 | 位置 | 生效方式 |
| --- | --- | --- |
| 当前镜头或片段的模糊强度 | MMD 附件操作 → `AdvancedMotionBlur.x` → **Si** | 实时读取。需要随时间轴变化时，注册附件关键帧 |
| 快门角、强度、拖影上限 | MMD 模型 → **AMB Controller** | 实时读取表情，可注册表情关键帧 |
| 参数基准值、采样质量、P1 与描边开关、顶点图集、调试视图 | [`src/Settings.fxh`](../src/Settings.fxh) | 修改现有的 `#define` 后让 MME 重编译。可只卸下并重新载入 `AdvancedMotionBlur.x` |
| 单个角色用骨骼速度还是镜头速度 | MME → Effect Mapping → **GeometryData** | 整个角色的行使用 `MotionGeometry.fx` 或 `DepthVelocity.fx` |
| 实际导出分辨率和帧率 | MMD 或导出工具 | 通过导出设置生效。拖影长度不随导出帧率变化，由快门角、强度和 Si 决定 |
| 描边本身的宽度、颜色和后处理顺序 | 模型、主材质、描边效果以及 MMD 绘制顺序 | 通过各自的设置生效。`MB_OUTLINE_MOTION` 控制描边怎样参与模糊 |

**Si=1** 是默认强度，**Si=0** 可在当前工程里对照有无模糊。修改 Si、重复播放和切换测试片段都可以继续用已载入的附件。对照时用连续播放或导出，因为暂停在同一帧会使历史速度归零。

## PMX 实时控制器

将 [AdvancedMotionBlurController.pmx](../src/AdvancedMotionBlurController.pmx) 作为模型载入，保持原文件名，再选中 **AMB Controller**。表情权重用 0 到 1。调好后在要生效的帧注册表情，连续播放或导出即可验证。

| 表情栏 | 表情 | 权重为 1 时 |
| --- | --- | --- |
| 眉 | `Strength +`、`Strength -` | 分别把 `MB_MOTION_SCALE` 倍率增至两倍或降至零，仍与附件 Si 相乘。基准 1.3 对应 0–2.6 |
| 眼 | `Shutter +`、`Shutter -` | 从 `MB_SHUTTER_ANGLE` 的基准分别调到 360° 或 0°。基准 180°，`+`=1 时曝光翻倍 |
| 口 | `Streak +`、`Streak -` | 分别把 `MB_MAX_STREAK` 增至两倍或降至零。1080p 下基准 64 px 对应 0–128 px |
| 其他 | `Threshold` | 在 `MB_SPEED_THRESHOLD` 上再加死区，1080p 下最多加 16 px。要更小的死区可直接改设置值 |
| 其他 | `Force Cut` | 权重达到 0.5 时，强制按切镜处理 |
| 其他 | `Keep Camera` | 权重达到 0.5 时，跳过自动切镜判定。与 `Force Cut` 同时生效时，以 `Force Cut` 为准 |

切镜表情可注册关键帧。只影响一帧时，在相邻帧注册 0。重复帧、倒放、历史缺失和过大的时间差仍由时间保护处理。旧 PMM 如果提示控制器模型结构变化，先用工程副本核对原有表情关键帧。新版追加两项，原有表情索引和分类保持一致。

未载入控制器，或载入后保持全部表情为 0，效果均沿用设置文件和 Si。快门和强度在公式里都是曝光时间的乘数，范围不同：`Shutter` 在 0–360° 之间，`Strength` 在基准的 0–2 倍之间。`Streak` 是独立的长度上限，`Threshold` 是独立的长度下限（死区）。

P1 轮廓外拖尾和描边修正不在控制器里。要对照时修改 `MB_EXTEND_FOREGROUND` 或 `MB_OUTLINE_MOTION` 后重载，关闭 P1 时也会去掉相应的渲染 pass 和渲染目标。

## 快门、强度与采样

| 参数 | 默认 | 取值和实际效果 |
| --- | --- | --- |
| `MB_SHUTTER_ANGLE` | `180.0` | 单位为度，着色器将范围限制在 0–360。按 30 fps 的一帧计算，与导出帧率无关：180° 的等效曝光为 1/60 秒，360° 为 1/30 秒。0° 关闭拖影。180° 沿用电影的"180 度快门"惯例 |
| `MB_MOTION_SCALE` | `1.3` | 全局无单位倍率，使用非负数。与附件 Si 相乘，常用 Si 做实时调整，使用本参数设定整套工程的基准。0.2.0 默认 1.0 |
| `MB_SCALE_STREAK_WITH_HEIGHT` | `1` | 按画面高度 ÷ 1080 换算拖影上限、死区、控制器量程和最小可见拖影。`0` 沿用固定输出像素 |
| `MB_MAX_STREAK` | `64.0` | 完整拖影的上限，使用非负数。1080p 默认以当前像素为中心向两侧各取最多 32 px，轮廓外拖尾的端部还有窄过渡 |
| `MB_SPEED_THRESHOLD` | `3.0` | 速度死区，使用非负数。每个像素的名义拖影先减去换算后的死区，再按换算后的 `MB_MAX_STREAK` 截断。想要只模糊快速动作，可从 `4.0`–`8.0` 试起，`0` 去掉这个死区 |
| `MB_QUALITY` | `1` | 同一表面的采样间隔按输出像素计。`0` 每 4 px 一个，`1` 每 2 px 一个，`2` 每 1 px 一个，至少 4 个，1080p 的上限分别为 32、64、128 个。`3` 固定 16 个。`MB_SCALE_STREAK_WITH_HEIGHT=1` 时，高于 1080p 的采样预算随画面高度增加，单循环上限为 255 个。轮廓外拖尾在 1080p 的独立采样预算为 64 个，也随高度增加 |

在连续渲染且历史有效时，着色器用两帧间的像素位移除以时间轴间隔，得到屏幕速度。拖影长度按以下关系计算，再用深度和覆盖范围筛选采样。

```text
等效曝光秒数 = (快门角 ÷ 360) ÷ 30
拖影长度 ≈ min(换算后的拖影上限, max(0, 屏幕速度 × 等效曝光秒数 × Si × MB_MOTION_SCALE − 换算后的死区))
```

例如 1080p 下速度为 600 px/s，按默认 180°、Si=1、强度 1.3 算出 13 px 的名义拖影，减去 3 px 死区后为 10 px。连续渲染时，30 fps 和 60 fps 使用同一套曝光换算。

快门角沿用电影常用的 180°，控制器 `Shutter +`=1 时为 360°，曝光翻倍。强度 1.3、1080p 上限 64 px 和死区 3 px 来自用户在控制器上调出的观感。

默认的完整拖影上限和死区在 1920×1080 为 64／3 px，在 3840×1728 为 102.4／4.8 px，在 3840×2160 为 128／6 px。最小可见拖影从 1080p 的 0.75 px 同步换算。原来为高分辨率手动调大过参数的工程，可以把数值折回 1080p 基准，或设 `MB_SCALE_STREAK_WITH_HEIGHT=0` 继续用原来的固定像素值。

## 前景拖尾、描边与深度

| 参数 | 默认 | 取值和实际效果 |
| --- | --- | --- |
| `MB_EXTEND_FOREGROUND` | `1` | `1` 启用 P1 的速度场、TileMax、NeighborMax 和轮廓外重建。较近的快速前景可把 RGB 拖尾带到白底或较远的物体上。`0` 回到 P0 的轮廓内重建，并跳过 P1 的速度场和分块归约 |
| `MB_LAYERED_TRAIL` | `0` | `1` 在主方向确定后选出不同深度的第二条方向，先合成远层拖尾，再叠近层。用于对照快速肢体旁背景拖尾消失的方块，依赖 `MB_EXTEND_FOREGROUND=1`。需要额外的两个分块纹理，各用独立的绘制步骤，重叠区最多沿两条方向采样 |
| `MB_TRAIL_SPREAD` | `0.35` | 轮廓外拖尾对方向偏差的容忍度。拖尾沿每个分块的主方向取样，而腿、手臂上各点的运动方向略有不同；容差固定在 1 px 时，只有方向刚好对齐的像素能接收拖尾，描边会碎成一列列点。现在容差随距离增加，每远 1 px 放宽 0.35 px（约 20°）。`0` 回到 0.2.0；数值越大越连续，但转动的部位可能向侧面糊开 |
| `MB_LINEAR_COLOR` | `1` | 轮廓内模糊读颜色时用线性过滤。采样点常落在两个像素之间，线性过滤读两者的混合，斜的细描边会均匀变淡，不再一段深一段浅。深度和覆盖判断仍用点采样。`0` 回到 0.2.0 |
| `MB_OUTLINE_SEARCH` | `3` | 原生描边像素向外找多远（像素）的模型表面来借用速度，每圈查 8 个方向，找到最近的一圈就停。描边常有 2–3 px 宽，外侧的描边像素四周没有模型表面，只查相邻像素时借不到速度，会保持清晰，斜的描边就成了虚线。只影响描边像素的开销 |
| `MB_OUTLINE_FRINGE` | `1` | 让描边抗锯齿后的柔边跟着描边一起模糊。MMD 主画面开着抗锯齿时，描边的深色会渗到相邻像素，而辅助缓冲不抗锯齿，把这些像素记成后面的背景，于是它们原地不动，在运动的轮廓上留下一串深色虚点。`1` 把紧挨原生描边、比描边更远的像素，以及轮廓上与描边同深度的半透明像素当作描边，借用附近模型表面的速度。`0` 回到 0.2.0；关掉 MMD 抗锯齿也能避开，但边缘会有锯齿 |
| `MB_EDGE_BACKGROUND` | `1` | 运动轮廓的内侧透出背景。`1` 时，同一表面的轨迹采样落在空白处或更远的物体上，按"物体移开时露出的背景"计入，轮廓从内到外连续虚化，手指、发丝这类比拖影还细的部位会变成半透明。`0` 回到 0.2.0：内侧保持实心，只有外侧的淡拖尾。半透明材质的采样仍不参与；比中心更近的物体仍由轮廓外拖尾处理 |
| `MB_OUTLINE_MOTION` | `1` | 在 P1 路径上，`1` 让原生描边参与辅助深度和速度重建，同时尝试识别已经合成进场景颜色的单像素暗线。`0` 仅关闭描边修正，保留 P1 轮廓外拖尾。此开关依赖 `MB_EXTEND_FOREGROUND=1` |
| `MB_DEPTH_TOLERANCE` | `0.045` | 对数深度容差，着色器最小按 `0.0001` 计算。同层采样在深度差不超过容差时取完整权重，在一至两倍容差间逐渐减弱，达到两倍时拒绝。默认相当于深度比约差 3.2% 开始衰减、约差 6.4% 完全拒绝 |

深度容差也影响 P1 对前后景的判断。有辅助深度的目标像素，只有在它比拖尾来源更远且差值超过容差时，才接收前景拖尾。原生描边可从两倍容差内的相邻表面继承速度。降低容差会缩窄同层采样范围，同时让更小的深度差也有机会被识别成前后景。

后处理描边修正要求暗线的两侧更亮，并位于深度边界。较宽、较浅的描边，以及在动态模糊之后才合成的描边，仍可能保留硬边。

## 时间差、切镜与底色

| 参数 | 默认 | 取值和实际效果 |
| --- | --- | --- |
| `MB_MIN_FRAME_GAP` | `0.0001` | 单位为秒。时间差必须严格大于此值，重复时间戳和倒放会显示当帧原色 |
| `MB_MAX_FRAME_GAP` | `0.1001` | 单位为秒。相机和顶点历史允许约 10 fps 的预览，或 30 fps 下跨两三帧。超过此值时回到当帧原色 |
| `MB_CUT_ANGLE_COS` | `0.7660444` | 分别比较相邻渲染帧的相机前向和上向。任一夹角的余弦低于阈值时清除本帧模糊。有效范围为 −1 到 1，默认约 40°。数值越高，切镜判断越敏感，例如 `0.8660254` 约为 30° |
| `MB_CUT_SCREEN_HEIGHT` | `0.15` | 取当前辅助几何的五处深度，重投影到上一帧，按有效样本的位移中值判定。中值超过画面高度的 15% 并且速度突增才判为切镜。设为 0 可关闭位移判定 |
| `MB_CUT_SPEED_RATIO` | `3.0` | 当前相机屏幕速度需要超过上一间隔的 3 倍。速度按时间轴差值归一化，以降低掉帧导致的误判。数值越大越倾向于保留连续运镜的模糊 |
| `MB_CLEAR_RGBA` | `1.0, 1.0, 1.0, 0.0` | 场景捕获缓冲的初始底色。用四个逗号分隔的 0–1 数值按 R、G、B、A 填写。默认 RGB 为白、Alpha 为零。最终输出沿用捕获到的 Alpha，P1 轮廓外扩张目前只覆盖 RGB |

首帧、暂停、倒放、输出尺寸变化及大幅缩放或投影变化也可能让效果暂时回到原色。导出从切镜前或片段前多留一帧，可给跨帧历史留出初始化时间。对于没有触发自动保护的小幅硬切，可在切入帧把附件 Si 设为 0 并注册。

## 角色速度与显存

| 参数 | 默认 | 取值和实际效果 |
| --- | --- | --- |
| `MB_AUTO_MODEL_MOTION` | `1` | `1` 默认把 PMX／PMD 映射到 `MotionGeometry.fx`，记录模型顶点历史，固定镜头时也能看到角色动作的模糊。`0` 默认使用 `DepthVelocity.fx`，可仍在 `GeometryData` 给指定角色手动开启顶点历史 |
| `MB_HISTORY_SIZE` | `512` | 每个使用 `MotionGeometry.fx` 的对象的方形顶点图集边长，使用正整数。容量为边长平方，按 MME 提供的顶点数和索引判断。超过容量时回退到镜头速度 |
| `MB_KEEP_OBJECT_MOTION_ON_CUT` | `0` | 实验项。设为 1 时改存投影前的世界坐标。普通帧用上一帧镜头计算速度，切镜帧用当前镜头投影上一帧顶点，只保留角色自身动作。需要所有参与效果的辅助映射都使用同一工作树的着色器 |
| `MB_TELEPORT_DISTANCE` | `50.0` | 仅在世界历史开启时生效。顶点在相邻有效帧之间移动超过 50 个 MMD 世界单位，就丢弃该顶点历史。普通帧保留镜头速度，切镜帧该处速度为零。纯相机移动不计入距离。设为 0 可关闭检查 |

开启实验项会增加一张全尺寸 RGBA16F 的角色速度缓冲，1920×1080 约 15.8 MiB，3840×1728 约 50.6 MiB。顶点图集的尺寸和数量保持原配置。建议先用 `MB_DEBUG=5` 检查角色是否为绿或蓝，再用 `MB_DEBUG=2` 对照切入帧。使用无压缩导出可核对背景归零和角色速度。

两张历史纹理合计在 512 时约 **8 MiB／对象**，在 1024 时约 **32 MiB／对象**，另有深度表面。工程已有的 `.emm` 显式映射可以覆盖默认值。如果固定镜头下角色没有拖影，先检查该角色整行在 **GeometryData** 的映射，并保留 **Main** 页的原材质。

## 调试视图

`MB_DEBUG` 默认是 `0`。以下视图要修改 [Settings.fxh](../src/Settings.fxh) 并重载效果。

| 值 | 视图 | 怎么读 |
| --- | --- | --- |
| `0` | 成片 | 使用当前配置的轮廓内模糊、前景拖尾和描边修正 |
| `1` | 原色 | 显示场景捕获颜色，可检查画面对齐 |
| `2` | 快门位移 | R、G 分别表示有符号的水平和垂直位移，0.5 为零，正方向为向右和向下。B 表示位移长度。此视图根据辅助几何和相机历史计算位移，P1 的轮廓外重建和描边速度修正仅在成片模式执行 |
| `3` | 深度 | 灰度显示辅助几何的对数深度，空白区为黑色 |
| `4` | 覆盖与速度来源 | 蓝色为镜头速度路径，绿色为有效顶点历史，红色为半透明或加法材质，黄色为捕获到的原生描边，黑色为无辅助几何 |
| `5` | 模型坐标诊断 | 只显示绑定本版本 `MotionGeometry.fx` 的几何。比较直接投影 `POSITION`、先乘 `WORLD` 再投影，与既有 `WORLDVIEWPROJECTION` 的 0.05 px 误差。绿为两种都通过，蓝为先乘 `WORLD` 通过，黄为直接投影通过，红为两种均超差 |

## 常用对照

| 要验证的现象 | 怎么设 |
| --- | --- |
| 整体有没有动态模糊 | 保持同一配置，连续播放同一小段，对比 MMD 附件 Si=0 和 Si=1 |
| P1 的拖尾有没有伸出轮廓 | 保持 `MB_DEBUG=0`，在 `Settings.fxh` 对比 `MB_EXTEND_FOREGROUND=0/1` 并重载。这会同时切换 P1 描边修正 |
| 单独看裙摆和两腿之间的硬线 | 保持 `MB_EXTEND_FOREGROUND=1` 和 `MB_DEBUG=0`，对比 `MB_OUTLINE_MOTION=0/1` 并重载 |
| 从 30 fps 改成 60 fps 导出 | 只改 MMD 或导出工具的帧率即可，每帧拖影的像素长度保持不变。想要 60 fps 物理快门的更短拖影时，把快门角减半，或在控制器眼栏注册 `Shutter -=0.5` |
| 恢复 0.2.0 的曝光与长度设置 | `MB_SHUTTER_ANGLE 180.0`、`MB_MOTION_SCALE 1.0`、`MB_MAX_STREAK 48.0`、`MB_SPEED_THRESHOLD 0.0`、`MB_SCALE_STREAK_WITH_HEIGHT 0` |
| 身体整体都糊，只想糊快速动作 | 调 `MB_SPEED_THRESHOLD`，或在控制器其他栏加 `Threshold`。降低 Si 或强度会让手的拖影一起变短，死区只削掉慢的部分 |
| 缩短或减轻拖影 | 先降低附件 Si。整段希望使用更短曝光时调小 `MB_SHUTTER_ANGLE`，希望只限制特别长的拖尾时调小 `MB_MAX_STREAK` |

## 预编译、载入与渲染速度

当前版本由 MME 在载入时编译 `.fx`。本地用 Windows SDK FXC 的 `/T fx_2_0` 实测，主效果和 `DepthVelocity.fx` 能生成 `.fxo`，`MotionGeometry.fx` 则因 MME 专用的顶点输入语义 `_INDEX` 被独立 FXC 拒绝（X4502）。临时改用 `TEXCOORD7` 可以验证编译，但真正的顶点索引绑定仍要由 MME 完成。整套预编译产物的 MME 加载兼容性尚未验证。

如果 MME 能直接接受等价的二进制效果，预编译能省下载入时的源码编译步骤。辅助效果映射、模型历史缓冲和渲染目标分配仍有各自的耗时。本机一次独立 FXC 检查中，主效果约 0.4 秒，`DepthVelocity.fx` 约 0.02 秒。这些数字只包含独立编译，不能用来判断 MME 里长时间卡顿的主要来源。

同一份着色器编译为相同的 GPU 指令时，提前编译基本不会提高逐帧渲染速度。实际影响渲染开销的是采样数、渲染 pass、输出像素数和顶点历史。`MB_QUALITY 0` 在短拖影上采样最少，`3` 固定 16 个，关闭 `MB_EXTEND_FOREGROUND` 会去掉 P1 的新增 pass，只给需要角色拖影的对象开启 `MotionGeometry.fx` 可减少顶点历史工作量。P1 单张全尺寸 RGBA16F 速度场在 1920×1080 约占 15.8 MiB，在 3840×1728 约占 50.6 MiB，另外还有小尺寸分块缓冲。

项目中的实机和离屏证据见 [验证记录](VALIDATION.md)。
