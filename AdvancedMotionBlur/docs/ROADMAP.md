# AdvancedMotionBlur 后续计划书

基于 0.2.0（提交 c7d7034）的代码审阅，2026-11-11 起草。主要目标是加强最终成片的画面表现。

本文列出的画面问题都是从着色器代码推出来的，起草时没有在 MMD 里重新渲染确认。每一项开工前先按“阶段 0”的对照帧复现问题，复现不了的项降级或删除。

2026-11-12 修订：工作区在 0.2.0 之上加了速度死区并调强了默认值（强度 1.3、上限 64 px、死区 3 px；快门角起初改成 270°，同日按用户要求改回 180°，因此曝光为 0.2.0 的 1.3 倍），尚未提交。下文的像素数字是按 270° 重算的，按 180° 时拖影约短三分之一，上限相关的数字不变；新增问题 K–P 已排进阶段，其中 M 降级、O 的修法改写，理由见各项。

## 现状评估

架构保留不动：深度加顶点历史得到速度，TileMax／NeighborMax 做轮廓外拖尾，切镜、跳帧、重复帧保护齐全。影响成片观感的问题集中在重建阶段。

| 编号 | 问题 | 代码位置 | 画面表现 |
|---|---|---|---|
| A | 运动物体的轮廓内侧完全不透明 | `AdvancedMotionBlur.fx` 的 `DepthWeight`，按深度差的绝对值拒绝采样 | 前景像素只和同层混合，背景透不进来。成片是“实心本体加外侧淡拖尾”，手指、发丝、飘带显得变粗而不是变虚 |
| B | 半透明像素完全不模糊 | `ExposureStreak` 对覆盖值大于 2.5 的像素返回零；`Geometry.fxh` 的 `DepthPixel` 把 Alpha 低于 0.985 或加法材质标为 3 | 发梢、睫毛、裙边等 Alpha 贴图区域在镜头摇移时独自清晰 |
| C | 长拖影出现台阶状重影 | `BlurSurface`：固定 8／16／24 个点，点采样，无抖动 | 16 个点铺 64 px 间距 4 px，控制器拉到 128 px 时 8 px。轮廓外拖尾的 64 点上限在 128 px 时间距约 2 px，一像素宽的前景会被漏采，细物体的拖尾可能断续。新默认值让这一项比起草时更明显。**轮廓内已有可选修法**（2026-11-12）：`MB_QUALITY` 0／1／2 按拖影长度分配采样数，间隔 4／2／1 px。用户一度要求默认保留 0.2.0 的固定 16 采样（`MB_QUALITY 3`），之后在基准对比中定为默认 `1`（2026-11-12）。抖动和轮廓外部分未改，以后改这一项要先确认风格取向 |
| D | 拖影上限和死区按像素写死 | `MB_MAX_STREAK` 为 64 px，`MB_SPEED_THRESHOLD` 为 3 px | 4K 下同样的动作更早被截断，模糊比 1080p 弱；死区在 4K 下也只有一半的效果 |
| E | 在伽马空间平均颜色 | `BlurSurface` 与 `ExtendForeground` 直接累加 8 位颜色 | 亮部拖影偏暗偏灰，高光拉不出光迹；平滑拖影有色带 |
| F | 轮廓外拖尾不写 Alpha | `Reconstruct` 沿用中心像素的 Alpha | 透明底导出丢失拖尾 |
| G | 附件只有镜头速度 | `GeometryData` 的默认映射把 `*` 交给 `DepthVelocity.fx` | 绑骨道具、移动的舞台部件没有自身模糊 |
| H | 每个分块只保留一个主方向 | `Foreground.fxh` 的 `AccumulateTile` | 相邻肢体方向不同时丢一条拖尾 |
| I | 模型瞬移时整体拖到上限 | 顶点历史只校验时间，不校验位移 | 换位的那一帧整个角色被拉满拖影 |
| J | 拖影只能是直线 | 速度取上一帧到当前帧的位移 | 挥臂、转圈的弧线运动拖成直线 |

| P | 预览低帧率时模糊整个关闭 | `MB_MAX_FRAME_GAP = 0.0501`；顶点历史还要求 `abs(dt - ELAPSEDTIME) <= 0.002` | 重场景预览约 15fps 时帧间隔约 67 ms，整帧显示原色（代码推断）；用户实测"无限制"约 500fps 时角色蓝绿闪烁。导出不受影响。候选修法：阈值提到约 0.1 s，去掉 ELAPSEDTIME 比较 |

### 对 K–P 的审阅（2026-11-12）

- **K 成立，但修法比表里写的大。** 顶点图集现在存的是上一帧的裁剪坐标（`RecordVertex` 写 `projected.xyw`），里面已经乘了上一帧的镜头。切镜时这份历史没法只取出角色自身的运动。3L 的做法是图集存投影前的顶点位置，切镜时把“上一帧矩阵”换成当前矩阵（`VelocityMap.fx` 的 `LastMatrix = IsSceneChanged() ? WorldViewProjMatrix : lastMatrix`）。我们要保留切镜帧的角色模糊，也得改成存投影前的位置。这项改动同时是 3.1、3.3 的基础，放到阶段 3 一起做。
- **L 成立。** 用现有 PMX 控制器加表情即可，不需要像 3L 那样另放附件。
- **M 降级为“不做，写进文档”。** MMD 的空白背景是纯色清屏，对纯色做模糊结果不变，画面上看不出差别。看得出差别的只有两处：角色轮廓外的拖尾（P1 已覆盖空白处）和轮廓内侧（1.1 处理）。如果把空白处当成无限远来算镜头速度，MMD 的背景图片和背景 AVI 是贴在屏幕上不随镜头动的，反而会被错误地模糊。需要背景随镜头模糊时用天空球或舞台几何体。用户反馈的“好像没有随镜头的模糊”在阶段 0 用 `MB_DEBUG=2`、`4` 另行排查，不归到这一项。
- **N 已实现，三点要注意。**
  - 死区减的是拖影长度，不是速度：调高快门或强度后，同样的动作会重新越过死区。参数名叫 SPEED，文档里要写清这一点。
  - 死区对镜头运动同样生效，慢速摇镜会完全没有模糊。这和 3L 一致，阶段 0 需要确认这是想要的观感。
  - 单位是输出像素，随 1.4 一起改成按画面高度。
- **O 成立，候选修法改写。** “位置跳变量除以画面中心深度”会误判环绕镜头：MMD 镜头绕注视点旋转时，镜头位置移动很大而画面主体几乎不动。3L 的判据是先扣掉旋转能解释的位移，再看剩余量（`IsSceneChanged` 的最近点计算）。更直接的办法是用屏幕位移判定：取画面上几个点的深度，用已存的上一帧矩阵重投影，位移的中位数超过画面高度的一定比例即判为切镜。这个判据对推拉、平移、旋转、变焦统一有效，环绕时主体不动所以不会误判，也不需要新的 slot。为了区分切镜和连续的快速运镜，再加一条：本帧位移要比上一帧的位移大数倍（切镜是单帧突变，运镜是连续的）。上一帧的位移量存进空闲的 slot 7。
- **P 成立，补一处。** 除了把 `MB_MAX_FRAME_GAP` 提到约 0.1 s、去掉 ELAPSEDTIME 比较，下限 `dt > 0.001` 也要放宽：预览约 500fps 时帧间隔只有 2 ms，贴着下限，这是蓝绿闪烁的另一个可能来源。放宽后速度仍按时间差归一，拖影长度不变。

**四、性能**

- 载入速度（已修，2026-11-12）：MME 用 `d3dx9_43.dll` 编译效果。`AdvancedMotionBlur.fx` 在它下面要编译约 20 s，新 FXC 只要 0.8 s。原因是 TileMax／NeighborMax 两个归约循环的次数要到运行时才知道，旧编译器优化时会逐次模拟循环，分别耗时约 7 s 和 10 s。改为固定上限加提前跳出，再把描边柔边修正里四次展开的环形搜索合并成一次后，降到约 2 s，效果字节码从 42 KB 降到 36 KB，FXC 72 次编译通过。归约循环的结果不变；柔边修正只在一种少见情况下不同：原来第一个相邻描边找不到表面时还会试下一个，现在只按第一个找。画面需要重新导出确认。`tools/d3dx_compile_time.py` 可以复测。还可以把 `AdvancedMotionBlur.fx` 预编译成二进制、仍用原文件名放回（共享经验 `mme-precompiled-effects`，SilverPalaceShader 验证过），省掉剩下的 2 s，但之后每改一次 `Settings.fxh` 都要重新生成，暂不采用。`MotionGeometry.fx` 用了 `_INDEX`，不能预编译，好在它本身只要 0.05 s。
- 运行时开销：没有实测过。先测再改：1080p 和 3840×1728 下分别读 MMD 帧率，对比不加效果、`MB_EXTEND_FOREGROUND 0`、默认三种。可能的改进点：
  - `CameraInterval()`、`ExposureScale()` 挪到全屏四边形的顶点着色器（1A.2 顺带做）。
  - `ExtendForeground` 每像素最多 64 次采样，NeighborMax 为零的分块可以整块跳过。
  - 双层拖影的第二遍分块搜索已复用横向归约。离屏归约的同深度和稀疏用例约从 0.24–0.37 ms 降至 0.03 ms，实际 MMD 帧时仍待测量。
  - 顶点图集每个模型约 8 MiB；模型顶点少时可把 `MB_HISTORY_SIZE` 降到 256。
- 编译余量：`BuildMotionField` 单独按像素着色器编译时报 X4505（临时寄存器超限），放在效果里能通过（效果编译可以把只依赖常量的计算移到预着色器）。以后改描边代码要用 `tools/d3dx_compile_time.py` 确认效果仍能编译，并且没有明显变慢。

## 阶段 0：对照基准与补验收

改任何重建代码之前完成，否则后面无法判断好坏。

1. 在 MMD 实机验收 0.2.0 的遗留项：控制器 PMX 载入与七个表情的实时绑定；用原全渲染工程对照 `MB_EXTEND_FOREGROUND=0/1` 和 `MB_OUTLINE_MOTION=0/1`。
2. 用 `test/` 里的工程固定一组对照帧，每帧导出原色（`MB_DEBUG=1` 或不加效果）、0.2.0 的结果和 3L v005 的结果（同工程、同帧、默认设置，作为 MMD 圈现有方案的参照），存在本地 `test/baseline/`（不入库）。3L 只在本地对比，不进仓库、不分发。帧：
   - 固定镜头，快速挥手或踢腿（问题 A、C、H、J）
   - 固定镜头，甩头时的发丝和睫毛（问题 A、B）
   - 镜头快速摇移，角色基本静止（问题 B、C）
   - 上述任一帧的 3840×1728 版本（问题 D）
   - 亮背景或带高光的帧（问题 E）
   - 一次切镜前后各几帧（问题 K、L）
   - 同角度、同 FOV、只改距离的切镜，以及一段快速环绕（问题 O，后者用来查误判）
   - 慢速摇镜和全身慢动作（问题 N，确认死区的观感）
   - 空白背景上的快速摇镜（问题 M，只用来确认降级的判断）
3. 参数分两套各导一遍：0.2.0 的默认值（180°／1.0／48／0）和当前默认值（180°／1.3／64／3）。之后的改动只和同一套参数的基准比，避免把参数变化算成算法变化。
4. 把帧号、相机、分辨率和导出设置记进 `docs/VALIDATION.md`，之后每项改动用同一组帧对比。

完成标准：遗留项有实机结论；每个问题至少有一帧能看出，或明确写“未复现”；每项都标明 3L 在同一帧上是更好、相近还是更差，用来调整后面阶段的顺序。

## 阶段 1A：时间与切镜（目标版本 0.3.0，先于重建）

这三项改动小，但直接影响能不能用：P 不修，重场景预览时看不到模糊，没法调参；O 不修，成片的切镜帧会闪一帧整屏拖影，比重建阶段的任何问题都显眼。

- **1A.1 预览帧率（问题 P）**：`MB_MAX_FRAME_GAP` 提到约 0.1 s，下限放宽，顶点历史去掉 ELAPSEDTIME 比较。验收：帧率限制 30、60、无限制和约 15fps 的重场景下，`MB_DEBUG=4` 里角色都稳定为绿色；导出结果与改动前逐像素一致。
- **1A.2 切镜判定（问题 O）**：按上面的屏幕位移加突变判据重写 `CameraInterval()`，保留朝向和投影类型两条旧判据作兜底。同时把 `CameraInterval()` 和 `ExposureScale()` 从逐像素计算挪到全屏四边形的顶点着色器里（现在每个像素都要重读三次镜头状态）。验收：只改距离的切镜帧显示原色；快速环绕和急摇不丢模糊。
- **1A.3 手动覆盖（问题 L）**：控制器加两个表情，一个强制本帧按切镜处理，一个强制不切，可注册关键帧。验收：两个表情都能压过自动判定。

## 阶段 1：重建质量（目标版本 0.3.0）

收益最大的四项。每项各带一个 `Settings.fxh` 编译开关，便于与 0.2.0 对照，稳定后再考虑删开关。

### 1.1 轮廓内侧透出背景（问题 A）

**已实现（2026-11-12，未实机验收）**：开关 `MB_EDGE_BACKGROUND`，默认 1。起因是用户实机反馈"模型内的模糊强于模型外"。`BlurSurface` 的采样权重改为 `TapWeight`：空白处和更远的采样按权重 1 计入背景，同层不变，更近的和半透明的仍拒绝。一维模型（16 采样、32 px 拖影）下，边缘从内侧 0 直接跳到外侧 0.52，变成从 0.11 到 0.44 再接到外侧 0.52 的连续过渡。

- 做法：`BlurSurface` 里，采样点比中心更远且差值超过容差时不再拒绝，改为按中心像素的拖影覆盖给权重，让背景颜色进入前景边缘。同层采样逻辑不变，比中心更近的采样点仍交给 `ExtendForeground`。
- 涉及文件：`src/AdvancedMotionBlur.fx`。
- 风险：背景采样点本身被别的前景挡住时会取到错误颜色，在多层交叠处可能串色。先只接受覆盖值为 0（空白）或不透明表面的背景点。
- 验收：挥手帧里手指两侧过渡对称，宽度小于拖影长度的物体中心不再是实色；静止物体和 Si=0 仍逐像素等于原色。

### 1.2 采样抖动与过滤（问题 C）

- `MB_SAMPLE_JITTER` 候选已实现屏幕像素固定相位，沿拖影方向偏移原有采样点。后台 D3D9 渲染了 64／128 px、各质量档，以及密采样的 512 px 一像素线。试用图显示默认档和旧版固定 16 点的规则条纹被打散。待用实际动作评估颗粒观感。
- 做法：每像素用屏幕坐标噪声偏移采样起点；颜色采样改线性过滤，几何缓冲保持点采样；采样数按拖影长度在档位上限内自适应。
- 涉及文件：`src/AdvancedMotionBlur.fx`、`src/Foreground.fxh`。
- 风险：抖动把重影换成噪点，静帧截图里可见。噪声用固定图案而不是随时间变化的，避免视频编码后闪烁。
- 验收：64 px 和 128 px 拖影在三个质量档下都看不到离散副本；一像素宽的前景在最长拖影下拖尾连续。

### 1.3 半透明参与模糊（问题 B）

**已实现候选**。普通 Alpha 材质可以同层模糊，加法材质继续保护。预乘捕获仍保留部分 Alpha 的普通材质可参加轮廓外拖尾。通过 D3D9 离屏对照，待 MMD 核对发梢、睫毛和眼镜片。

- 做法：覆盖值 3 的像素也写入速度（顶点历史可用时用顶点速度，否则用镜头重投影），重建时按颜色 Alpha 加权。加法材质继续保护。
- 涉及文件：`src/Geometry.fxh`、`src/AdvancedMotionBlur.fx`、`src/Foreground.fxh`。
- 风险：辅助深度每像素只有一层。眼镜片这类盖在别的表面前方的透明层，会把后面的内容按前层速度拖动。提供开关回到 0.2.0 的保护行为，并在参数手册写明适用情况。
- 验收：镜头摇移帧里发梢和睫毛与头发主体的模糊程度一致；眼镜、特效贴片不出现明显错位。

### 1.4 拖影上限按画面高度（问题 D）

**已实现**。数值仍用 1080p 参考像素填写，`MB_SCALE_STREAK_WITH_HEIGHT` 默认打开。关闭后沿用固定输出像素。D3D9 离屏已在 1280×720、1920×1080、3840×1728 和 3840×2160 对照，原工程的 MMD 导出待复查。

- 做法：上限和死区都改为画面高度的百分比，默认值取 1080p 下等于现在的 64 px 和 3 px（约 5.9% 和 0.28%）。`MinStreak`、NeighborMax 搜索半径、控制器 `Threshold` 的 16 px 量程同步换算。
- 涉及文件：`src/Settings.fxh`、`src/Controller.fxh`、`src/AdvancedMotionBlur.fx`、`src/Foreground.fxh`、`docs/PARAMETERS.md`。
- 风险：参数含义变了，旧工程里改过 `MB_MAX_STREAK` 的需要换算。在 CHANGELOG 里写明。4K 下拖影更长，`ExtendForeground` 的 64 点上限需要一并复核。
- 验收：同一帧在 1920×1080 与 3840×1728 下缩到同尺寸后拖影长度一致。

## 阶段 2：色彩与输出（目标版本 0.4.0）

- **2.1 线性空间累加（问题 E）**：`MB_LINEAR_LIGHT` 候选已实现 sRGB 转线性、累加与转回，离屏验证了内外拖影、静止画面与预乘 Alpha。待用 MMD 的亮背景帧对照实际观感。高光加权仍为后续方案。
- **2.2 输出抖动（问题 E）**：`MB_OUTPUT_DITHER` 候选已实现固定的 4×4 最终量化。离屏对照中，17 个小数色阶的区域平均值正确，静止区域逐像素不变，512 px 的细线拖尾量化后仍有亮度差。待在 MMD 实际导出中核对大面积平滑拖影的色带和图案可见度。
- **2.3 拖尾写入 Alpha（问题 F）**：`ExtendForeground` 同时累加覆盖，写进输出 Alpha，按预乘色约定输出。验收：透明底导出后在黑底和白底上合成，拖尾都正确、无亮边或暗边。

## 阶段 3：速度来源（目标版本 0.5.0）

- **3.0 顶点历史改存投影前的位置（问题 K 的前提）**：图集从存裁剪坐标改为存世界空间位置，上一帧的镜头矩阵单独用。这样角色自身的运动和镜头运动可以分开算。需要先实测 MME 里 PMX 的 `POSITION` 是否已是世界空间、附件是否要乘 `WORLD`。验收：不切镜时速度缓冲与改动前一致（`MB_DEBUG=2` 逐像素对比）。
- **3.1 切镜帧保留角色模糊（问题 K）**：切镜时用当前镜头矩阵重投影上一帧的位置，只留角色自身的运动。验收：切入帧角色有动作模糊，背景和静止物体为原色。
- **3.2 附件自身运动（问题 G）**：附件是刚体，记录上一帧的世界矩阵即可（3L 的 `lastWorldMatrix` 就是这样做的），每个对象只多几个纹素，不需要整张顶点图集。验收：绑骨道具有自身模糊，静止舞台的速度缓冲不变。
- **3.3 多方向拖尾（问题 H）**：`ExtendForeground` 的采样一半沿 NeighborMax 方向，一半沿中心像素自身方向。
- **3.4 瞬移保护（问题 I）**：3.0 之后可以按世界空间的位移判断，超过阈值时该顶点的历史判无效，回到镜头速度。

## 阶段 4：风格与上限（不排版本）

- **4.1 快门曲线**：增加拖尾偏向运动后方的选项，做成控制器表情。属于风格功能，默认保持对称。
- **4.2 弧线运动（问题 J）**：多存一帧顶点历史估计加速度，或交给 4.3。
- **4.3 子帧累积**：配合 MMDEncoder 做 2–4 个子帧，每个子帧用较短快门。能同时解决弧线运动、阴影和多层透明的模糊，是画质上限方案，代价是导出时间成倍增加。
- **4.4 兼容性**：验证并写明与 Ray-MMD、sdPBR、景深、泛光、Croquis 的附件绘制顺序。

## 执行约定

- 开工前先把工作区里的死区和新默认值单独提交，作为之后所有对比的固定起点。
- 顺序：阶段 0 → 1A.1 → 1A.2 → 1A.3 → 1.2 → 1.1 → 1.4 → 1.3。1A 改动小且影响预览和切镜帧，先做；1.2 让后面几项的对比更干净；1.3 风险最高，放在最后。
- 每项单独提交，提交前跑完整 FXC 编译矩阵（质量档、调试视图、各开关组合），并用阶段 0 的对照帧出前后对比图。
- 实机结论、离屏结论和“未运行”分开记进 `docs/VALIDATION.md`，不把编译通过写成画面验收。
- 发布按 `CLAUDE.md` 的流程：版本号写进 README 标题和 CHANGELOG，标签推送前先确认。
