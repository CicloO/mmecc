# P0 基线、P1 验证与后续计划

## 带场景时右手旁的清晰方块

- 在用户的 `test/测试12.avi` 抽取 10.133、10.200、10.267 秒原帧。10.200 秒手旁的栅栏拖尾突然变清晰，左边界约 x=704，上下约 y=295／524，和 1920×1080 下约 32 px 的速度分块对齐。前后抽帧没有同一片清晰区域。相邻 EMM 给角色和舞台都分配了 `MotionGeometry.fx`。
- 单方向竞争是最符合现象的解释。D3D9 离屏用快速竖向近景、较慢横向栅栏和静止遮挡复现了这个机制。原单方向在栅栏间隙输出 `FFFFFF`，开启 `MB_LAYERED_TRAIL=1` 后恢复到 `E6E9EC`，与单独渲染栅栏的同一像素一致。近景拖尾、遮挡和 Alpha 检查通过。103×69、1920×1080、3840×1728 三组输入均通过。相同速度场输入下，开关为 0 时重建结果与 `d995506` 逐像素一致。
- 初版 FXC 矩阵 26 组、78 次通过。用 `d3dx9_43` 编译成片配置，默认 2.15 秒，开启双层 4.16 秒。初版用同一 pass 的两个渲染目标，修订版改为分别绘制。
- 实机对照使用 `测试基线_带场景.pmm` 的副本，从独立工作树载入附件。检查 `GeometryData` 中的角色和舞台路径。用同一范围分别导出 `MB_LAYERED_TRAIL=0/1`，看 10.200 秒附近的栅栏和手部。保留白背景附件和绘制顺序。
- 双层候选的扫描顺序另有一处可复现的漏选。D3D9 HAL 在同一分块按顺序写入四个像素，拖尾长度和对数深度分别为 (10, 1.0000)、(9, 1.1250)、(8, 0.8750)、(12, 1.0625)。最后一个像素当选主速度时，原候选 9 px 因深度接近被清除，仍满足深度差的 8 px 没有补进来。把 12 px 放在扫描首位即可取到 8 px。两遍扫描的临时实现对这两种顺序均取到 8 px，`d3dx9_43` 编译由 4.24 秒增至 6.04 秒，暂未合入。原视频里的清晰方块是否也受这项漏选影响，需结合原场景速度和深度图核对。
- 修订版以横纵归约找主速度，再分别选分块和邻域的第二层。两个顺序的四样本用例在分块和邻域均保留 8 px，主方向与深度逐字节一致。63×63 恢复右下侧拖尾。103×69、1920×1080、3840×1728 的手和栅栏场景与旧双层版逐像素一致，遮挡、Alpha 和零曝光对照通过。默认单层在 1080p 和 3840×1728 的四种测试负载下归约结果逐字节一致。
- RTX 5090 D 的离屏时间戳只计归约。1920×1080 密集速度场从 0.254 ms 增至 0.279 ms，稀疏场从 0.257 ms 增至 0.274 ms。3840×1728 分别从 0.349 ms 增至 0.366 ms、从 0.351 ms 增至 0.368 ms。零曝光由约 0.005 ms 增至 0.012–0.013 ms。FXC 32 组 96 次通过，`d3dx9_43` 双层主效果约 3.72 秒，双层与切镜保留角色同时开启约 3.54 秒。
- 待用修订版在 MME 验证横向归约目标和同一工程的画面，双层开关仍为候选。双层拖尾每个分块最多保留两个方向。

## 切镜位移判定

- 相机判定和曝光放进 1×1 pass。旧相机纹理在该 pass 中只读，帧末把速度写入其第 7 个索引。现有 D3D9 顶点纹理读取要求不变。
- RTX 5090 D 的离屏 D3D9 回读通过了同角度推拉、平移硬切、持续快速平移、普通小幅平移、朝向与无几何时的缩放兜底、首帧、重复帧、倒放及间隔范围。合成深度和镜头矩阵由测试直接注入，未经过 MME。
- FXC 矩阵 25 组、75 次编译全部通过，默认成片配置 `d3dx9_43` 为 2.01 秒。未运行基线工程的 531／751／831 和连续运镜对照，尚未确认实机误判率和普通帧像素一致性。
- 控制器加入手动切镜后，离屏通过强制切、强制不切、两项冲突优先级和无效历史保护。离线读取 PMX 确认原七项顺序及分类、两个新增表情所在的其他栏和表情显示框索引。FXC 75 次通过，`d3dx9_43` 成片配置 2.07 秒。未运行原生 MMD 表情绑定或旧 PMM 载入验证。

## 顶点历史坐标诊断

- `MB_DEBUG=5` 比较 `POSITION` 的两条投影路径与现有 `WORLDVIEWPROJECTION` 的像素误差，作为记录投影前位置的实机检查。绿为两条一致，蓝为先乘 `WORLD` 一致，黄为直接投影一致，红为两条均超差。
- FXC 矩阵 27 组、81 次通过。默认 `d3dx9_43` 成片配置 2.15 秒，诊断主效果 0.07 秒，诊断顶点辅助效果 0.05 秒（临时副本使用 `TEXCOORD7`）。未运行 MME 的实际顶点输入验证。

## 切镜帧的角色速度

- `MB_KEEP_OBJECT_MOTION_ON_CUT=1` 将顶点历史从裁剪坐标换成世界坐标，旧格式时间戳与新格式分开。普通帧用上一帧镜头投影旧顶点，切镜帧用当前镜头投影。主画面读取独立的角色速度，并在帧末清空该目标。开关默认关闭。
- D3D9 离屏在几何 VS／PS 注入旧图集、镜头纹理和带 `WORLD` 平移的三角形。普通帧几何目标与旧路径逐像素一致；约 24 px 的镜头加角色位移在切镜时切换为约 8 px 的角色位移。无几何和不透明背景的位移归零，旧镜头在模型后方仍能取到角色速度，过期镜头时间戳和半透明保护也通过。测试直接绑定了两张渲染目标，未经过 MME。
- FXC 矩阵 31 组、93 次通过。默认和开启时的 `d3dx9_43` 主效果分别为 2.15／2.17 秒，开启时的顶点辅助效果为 0.08 秒，辅助效果独立编译使用临时替换后的 `TEXCOORD7`。
- 未运行原生 MME 的 `MB_DEBUG=5`、共享镜头历史与双目标绑定、基线 531／751／831 切入帧对照。旧坐标路径和世界坐标路径的普通帧实机一致性仍待验证。
- 瞬移保护离屏测试中，50 世界单位的相邻帧位移继续使用历史，50.125 单位切到镜头速度，切镜帧归零。普通角色运动和纯相机运动分别通过逐像素与状态检查。FXC 32 组、96 次通过。默认／世界历史主效果的 `d3dx9_43` 时间为 2.15／2.16 秒，世界历史辅助为 0.08 秒。未运行 MMD 模型瞬移的实机画面。

## 无曝光帧的分块开销

- TileMax 和 NeighborMax 读取本帧 1×1 相机分析，只在历史失效或曝光为零时写空速度。开启世界历史后，切镜帧的有效角色速度仍进入归约。
- RTX 5090 D 离屏 D3D9 时间戳，比较两道归约 pass，每组 24 次，取五组中位数。无曝光时 1920×1080 从 0.285 ms 降至 0.005 ms，3840×1728 从 0.412 ms 降至 0.005 ms。无曝光、正常运动、世界历史切镜有角色速度时的归约输出均逐像素一致。只测这两道 pass，未测整帧和原生 MMD 帧率。
- FXC 32 组、96 次通过。`d3dx9_43` 默认／世界历史主效果为 2.18／2.16 秒。
- 后续试验用 `d3dx9_43` 实际运行完整的速度场、分块和重建，比较在最后一道全屏 pass 按分析纹理或按速度场标记直接返回原色的写法。1080p 和 3840×1728 在默认、P0、双层、透明和世界历史配置下输出逐像素一致。大多数无曝光负载的差值只有几微秒，有效曝光也出现小幅增耗。两种写法均未合入。

## 预览时间差

- 相机和顶点历史按时间轴差值接受 `0.1 ms < dt ≤ 100.1 ms`，顶点路径继续校验图集索引、有效时间戳与投影深度。移除与宿主 `ELAPSEDTIME` 的二次比对，模糊长度仍按实际时间差归一化。
- Windows FXC 矩阵 24 组、72 次编译全部通过。相同机器的 `d3dx9_43` 成片配置由基准 2.00 秒到 2.00 秒，顶点辅助效果为 0.05 秒，独立编译使用临时的 `TEXCOORD7` 替代 `_INDEX`。
- 未运行原生 MMD 的 30／60 fps、无限制及约 15 fps 预览，尚未确认 `MB_DEBUG=4` 的顶点历史稳定性或基线 AVI 像素一致性。

## 技术依据

| 项目 | 实现 |
|---|---|
| MME 捕获场景 | 使用 `ScriptExternal=Color` 捕获场景，`OFFSCREENRENDERTARGET` 单独为对象分配辅助效果 |
| 深度 | D24S8 用于辅助几何遮挡测试。着色器将 `log2(viewZ)` 写入 RGBA16F 的 B 通道，供后处理采样 |
| 运动矢量 | 从深度与上一帧相机矩阵重投影。实验性模型路径按顶点索引记录变形后齐次投影坐标 |
| 跨帧状态 | 使用相机历史和顶点图集，校验时间、输出尺寸和顶点时间戳 |
| 透明材质 | 用材质 Alpha 与贴图 Alpha 估计覆盖，半透明和加法材质使用原色保护 |
| D3D9 / SM3 | 使用 `vs_3_0`、`ps_3_0`、浮点颜色 RT 与点采样。模型路径额外需要顶点纹理读取和 MME 的 `_INDEX` |

参考 [MME 0.37 参数](https://kamedesuyo.github.io/MME_REFERENCE/sections/section2.html)、[MME Script](https://kamedesuyo.github.io/MME_REFERENCE/sections/section3.html)、[Microsoft ps_3_0](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx9-graphics-reference-asm-ps-3-0)。

- 数学参考测试覆盖静止相机、平移、旋转与垂直方向符号，验证了 30/60 fps 快门缩放、速度上限、重复帧和倒放的历史条件、跨层深度拒绝及 512² 图集索引边界。

## P1 前景拖尾

- `Foreground.fxh` 把像素速度、对数深度和几何覆盖写入全分辨率 RGBA16F。TileMax 按约 32 像素宽的分块找主速度，NeighborMax 把搜索方向传播到可能被拖尾覆盖的邻近分块。重建时按源像素自身的速度和深度检查它能否覆盖目标。远处和空白处可接收较近的拖尾，较近的遮挡层和半透明像素保留原色。 [Guertin 等人的特征感知重建](https://research.nvidia.com/publication/2013-11_fast-and-stable-feature-aware-motion-blur-filter)
- `MB_EXTEND_FOREGROUND=0` 可对照 P0。关闭时和调试模式下跳过新渲染目标及三个新 pass。开启时额外的全分辨率速度纹理约占 15.8 MiB（1920×1080）或 50.6 MiB（3840×1728），另有小尺寸分块纹理和深度表面。
- Windows SDK FXC 编译通过三个质量档、四个调试视图和关闭扩张的回退路径。
- RTX 5090 D 上用 D3D9 HAL 离屏执行四个 P1 像素着色器，在 103×69／30、1920×1080／60、3840×1728／30 的合成图上通过像素检查。分别注入固定镜头下的模型速度和纯镜头位移，检查细前景跨分块拖到白底和远层、近层遮挡、半透明保护、最右边缘、输出 Alpha，以及重复帧、跳帧、切镜和 Si=0 时回到原色。 [离屏对照图，左为原色，右为 P1](validation/P1-offscreen-foreground.png)
- 原生 MMD 分别完成 P0 对照和 P1 的 640×362、30 fps、35 帧 AVI 导出。这个环境里的 `BlurP0_Stage.x` 在卸下模糊效果后仍输出白画面，两段 AVI 只证明载入和导出完成，无法判断拖尾。

## P1 描边修订

- 全渲染工程的 EMM 为角色分配了 `MotionGeometry.fx`，同时包含 Croquis 后处理。修订前辅助几何的 `edge` pass 为空，主画面与速度缓冲在外轮廓上会产生覆盖差异。
- MMD 原生描边使用宿主已扩张的顶点写入辅助深度。模糊重建从相邻同深度表面借用速度。已合成进场景颜色的单像素暗线通过两侧颜色和前后景深度约束识别。两条路径共用现有运动缓冲。
- FXC 通过主效果的三个质量档、四个调试视图、关闭描边和 P0 回退的配置。深度及顶点辅助效果通过编译，后者在临时副本中用 `TEXCOORD7` 代替 MME 专用 `_INDEX`。
- RTX 5090 D 的 D3D9 离屏测试通过 103×69／30、1920×1080／60 和 3840×1728／30。检查了原生描边覆盖编码，前景速度与深度继承，空底和远层上的单像素暗线，同层暗纹、半透明保护、静止原色、Alpha 和 Si=0 对照。
- 待用原全渲染工程验收 MME 原生描边顶点绑定和 Croquis 合成顺序。用同一段裙摆或小腿运动对照 `MB_OUTLINE_MOTION=0/1`。后处理描边厚度超过一像素时仍可能出现残余硬线。

## P1 PMX 控制器

- 用户反馈后修订：P1 与描边开关移出控制器，只保留在 `Settings.fxh`；`Streak ±` 从眉栏移到口栏。`MB_OUTPUT_FPS` 及 `FPS 30/60` 表情删除，快门角固定按 30 fps 的一帧计算。屏幕速度按秒计算，帧率参数和快门角、Si、强度在公式里是同一个乘数，可以互相替代；固定 30 后，60 fps 导出也保持 30 fps 时期的拖影长度（此前把帧率设为 60 会让拖影减半）。
- `tools/build_controller.py` 用 Python 3.14 重新生成的 PMX 与 `src/AdvancedMotionBlurController.pmx` 逐字节一致（1007 字节）。按 PMX 2.0 规格逐段解析到文件末尾：UTF-16LE、全部索引 1 字节，一个 Alpha 为 0、无描边无阴影的材质，一根 Root 骨骼，6 个零偏移顶点表情（眉 2、眼 2、口 2），Root 与表情两个特殊显示枠，无刚体和关节。`Controller.fxh` 读取的 6 个 `item` 名与 PMX 表情名一一对应。
- 速度死区（2026-11-12，未发布）：`ExposureStreak` 中拖影先减去 `MotionSpeedThreshold()` 再截断，死区由 `MB_SPEED_THRESHOLD` 加控制器单个表情 `Threshold`（最多 +16 px）决定。默认值同时改为强度 1.3、上限 64 px、死区 3 px，快门角保持 180°（曾短暂改为 270°，用户要求改回）。轮廓内模糊新增按拖影长度分配采样数的档位（`MB_QUALITY` 0／1／2 = 间隔 4／2／1 px，最少 4、最多 32／64／128 个），中心权重按原 16 点核的比例随采样数缩放；`MB_QUALITY 3` 固定 16 采样，与 0.2.0 的核逐项相同。默认值曾设为 3，用户后来定为 `1`（2026-11-12）。FXC 另加 `MB_QUALITY=3` 及其与 `MB_EXTEND_FOREGROUND=0` 的组合，共 45 次编译通过。

## 单层速度分块归约

- 原循环每轴最多读取 40 px。视口为 63×63、`ViewPortRatio` 向下取整时，单个分块覆盖整个视口。D3D9 HAL 中分别在 (60,30)、(30,60)、(62,62) 放置一个有速度的像素，原版在三个用例均输出零速度，横纵两步归约均在 `TileMax` 和 `NeighborMax` 中读回该速度。
- 用含等长异向速度、不同深度和零速度的合成数据对照 103×69、1920×1080 和 3840×1728。有效曝光和零曝光各跑一遍，两张归约纹理的 RGBA16F 数据逐字节一致。
- RTX 5090 D 后台 GPU 时间戳只计分块和邻域归约，含新横向 pass。1920×1080 的有效曝光由 0.247 ms 降至 0.022 ms，3840×1728 由 0.351 ms 降至 0.029 ms。零曝光两种尺寸约从 0.005 ms 增至 0.008 ms。新增横向颜色和深度目标按 RGBA16F／D24S8 估算占 0.74 MiB 和 2.37 MiB。
- FXC 32 种配置共 96 次编译通过。`d3dx9_43` 的默认主效果从 2.16–2.19 秒降到 1.05 秒。当时双层候选仍用双输出归约，主效果编译约 4.09 秒。
- 待在 MME 核验横向渲染目标的实际尺寸、连续导出与画面。上面的 GPU 数据为后台 D3D9 离屏测试。

## 运行时邻域范围

- 采用 `[fastopt]` 按实际拖影上限搜索邻域，行和列以最多 255 个分块分段。后台 D3D9 在 300×1 和 1×300 分块的合成输入中，均从首个分块读回第 300 个分块的有效速度。

## 分辨率换算

- 默认 `MB_SCALE_STREAK_WITH_HEIGHT=1` 使用画面高度 ÷ 1080 缩放上限、死区、`Threshold` 的附加量程与最小可见拖影。后台 D3D9 读回 540–4320 高度的参数，通过控制器 `Streak +`、`Threshold` 与采样预算检查。30／60 fps 注入相同的每秒速度，各尺寸的死区上下和上限对照均通过。
- 用按高度缩放的移动条，通过速度场、分块、邻域和重建后，测量轮廓外单侧拖影并折算到 1080p 像素。1280×720、1920×1080、3840×1728、3840×2160 分别为 31.50、32.00、31.88、31.50 px，关闭换算时分别为 46.50、32.00、20.00、16.00 px。1080p 的开关对照逐像素一致。关闭换算后四种尺寸均与前版逐像素一致。2160 高度的双层与 `Streak +` 组合也通过四分块外拖尾回读。
- 速度场的独立着色器测试关闭了描边修正。成片配置保留描边，FXC 34 组共 102 次通过，含关闭换算、双层、切镜历史、各质量档和调试模式。`d3dx9_43` 默认主效果约 1.07 秒，双层约 2.23 秒。
- 待在 MMD 同一帧分别导出 1920×1080 与 3840×1728 对照。按画面高度对齐两张图后核对拖影长度。

## 透明底拖尾

- 用 D3D9 HAL 将直通 RGBA 场景按预乘方式捕获后，运行速度分块和最终重建。在同一轮廓外像素，旧路径读回 `00FAE9EC`，有拖尾 RGB、Alpha 为零。启用 `MB_TRAIL_ALPHA=1` 后读回 `1A160407`（均按 AARRGGBB 记），Alpha 为 26/255。
- 103×69、1920×1080、3840×1728 均验证了静止画面、内侧淡化、外侧覆盖、双层先远后近、近景遮挡、半透明保护和带 Alpha 的描边样本。关闭轮廓外拖尾时，P0 路径只更新轮廓内侧的 Alpha。预乘图分别合成到黑底和白底，与直接渲染到对应不透明底色的结果相差不超过 2 个 8 位色阶。关闭开关的对照与前一提交逐像素一致。
- FXC 39 组共 117 次通过。`d3dx9_43` 编译默认和透明主效果均约 1.03 秒，透明双层约 2.15 秒。用同一 DLL 实际创建效果并读回清屏参数，普通配置为 `1,1,1,0`，透明配置为 `0,0,0,0`。
- 开发分支保持候选关闭。实机需确认 MME 捕获的场景 Alpha、导出文件的 Alpha，以及按预乘方式合到黑底与白底的外观。离屏测试使用 D3D9 的独立 Alpha 混合，未覆盖 MMD 的材质混合、导出器或其他 MME 的合成顺序。

## 附件矩阵历史

- `MB_ACCESSORY_MOTION=1` 将 `.x` 映射到 `RigidMotion.fx`。首材质保存前一帧快照，各材质读同一份矩阵。上一帧世界矩阵与共享相机历史必须有相同时间戳。矩阵完全相同的附件继续走原深度路径。
- 192×128 D3D9 HAL 用真实顶点和像素着色器读取保存、复制后的矩阵。固定镜头下平移读回 12 px，叠加镜头平移为 24 px，开启切镜保留物体时单独读回 12 px。旋转、静止附件与旧深度路径逐字节一致、两套独立附件缓冲、过期或缺失历史、倒放、重复帧、分辨率变化、瞬移、半透明和坐标诊断均通过。
- 固定镜头下，实际几何速度经过速度场、归约和重建，在当前三角形轮廓外产生 768 个拖尾像素。相同位置的静止三角形逐像素等于原色。离屏重建的速度场关闭了描边修正。PMX 世界顶点历史的普通帧和瞬移临界值回归通过。
- FXC 42 组共 168 次通过。旧版编译器编译候选主效果约 1.03 秒，`RigidMotion.fx` 约 0.09–0.10 秒。附件效果不使用 `_INDEX`。
- 待在 MMD 中验收 `WORLD` 绑定、首材质脚本、共享相机与多附件各自的历史。固定镜头下分别移动和旋转两件附件，再用静止舞台配移动镜头做对照。开关在开发分支保持候选关闭。

## 模型与相机帧间隔

- 默认裁剪坐标历史原先只检查各自的时间差是否落在合法区间。后台用模型少记一帧而相机连续记录的输入，复现了旧版在 30、500 和 8000 fps 合成用例中仍套用过期位移。
- 现将模型帧间隔写入辅助几何纹理的覆盖通道，由合成阶段在半精度容差内和相机间隔核对。无需新增纹理。错配时固定镜头的合成速度归零，移动镜头下回到逐像素镜头重投影，调试 4 显示蓝色。
- 192×128 和 1920×1080 用实际顶点记录、几何和合成着色器验证。同步的 10、15、30、60、500、8000 fps 输入在速度和深度调试图逐像素一致，描边借速和切镜深度探针识别到新记录。FXC 42 组共 168 次通过，`d3dx9_43` 默认主效果约 1.05 秒。待在 MMD 用隐藏再出现的模型连续导出复查。

## 长拖影的细线采样

- 在 1920×1080 的 D3D9 重建中，一像素宽的黑线以 128 px 水平拖影长度测试。旧版在内部 120 个采样位置中有 60 个保持白色，`MB_DENSE_FOREGROUND_TAPS=1` 后为 0。3840×2160 的 256 px 水平用例从 124／248 个空白点降至 0，斜向由 50／172 降至 0。40 px 短拖影逐像素一致。关闭开关的重建像素着色器与前版的 FXC 字节码一致。
- 576×1080 的边缘和长循环对照，以及 512 px 的浮点重建通过。512 px 水平用例中，密采样后单像素黑线的每点覆盖约为 1/512，8 位输出会把该点的差异舍入为零，浮点回读仍连续。
- RTX 5090 D 的合成线条只测最终重建。1080p 的 128 px 用例约 0.024→0.032 ms，4K 的 256 px 用例约 0.066→0.082 ms。FXC 44 组共 176 次通过，`d3dx9_43` 候选主效果约 1.08 秒，双层与透明组合约 2.28 秒。
- 开关默认关闭，待在 MMD 用较大的 `Streak +` 对照细线或描边，并核对成片的拖影质感与实际耗时。

## 普通 Alpha 材质的模糊

- 用 `d3dx9_43` 创建实际几何效果并绘制 Alpha 贴图，得到普通半透明 −1、不透明 1、裁切 0 和加法材质 6。另用实际模型顶点记录、几何 VS 和半透明 PS 验证普通 Alpha 保留正确的模型位移和间隔，加法材质保持零速度。
- 320×1080、1920×1080、3840×1728 使用旧版运行库绘制速度场、归约和重建。关闭开关时与前版的速度场和画面逐像素一致。开启后通过镜头、模型、切镜自身速度、P0、同层混合、不同深度拒绝、近景遮挡和描边旁的加法保护对照。已叠到不透明底色的更快半透明区域未取代分块的主方向或第二方向。预乘捕获中同一外侧样本的 Alpha 在 1080p 为 31/255，在 3840×1728 为 32/255。
- FXC 50 组共 200 次通过，`d3dx9_43` 默认／候选主效果约 1.07／1.10 秒，候选加预乘和双层约 2.25 秒。开发分支默认关闭。待在 MME 核对加法标志、头发和睫毛的运动、眼镜片、已有背景下的边缘，以及透明捕获链。

## 线性光累加

- 用 `d3dx9_43` 实际执行最终重建。320×1080、1920×1080、3840×1728 的黑白各半用例，轮廓内 RGB 从 127/255 变为 188/255，P0 也符合线性光结果。轮廓外白拖尾叠在黑底时从 90/255 变为 160/255，符合按 sRGB 曲线转回的预测。
- Alpha 为 128/255 的黑白混合得到预乘 RGB 94/255，Alpha 保持 128/255。透明白拖尾的 RGB 与 Alpha 一致，合成到黑底后符合线性光公式。两种不同颜色的拖尾按远到近叠加，与独立计算的结果相差不超过 2 个 8 位色阶。关闭开关与前版逐像素一致，静止画面通过全帧对照。
- 合成场景覆盖 20% 的有效模糊区域，RTX 5090 D 的重建时间在 1080p 约 0.0020→0.0023 ms，3840×1728 约 0.0033→0.0037 ms。仅测最终重建。FXC 56 组共 224 次通过，`d3dx9_43` 默认和线性光主效果均约 1.09 秒。
- 开发分支默认关闭。待在 MMD 用亮背景和高反差物体对照成片观感和实际耗时。

## 同版本组合与实机对照

- FXC 58 组共 232 次通过。新增 `reviewscene` 与 `reviewrgba`，同时覆盖双层、切镜保留物体、附件矩阵、长拖影采样、普通 Alpha 与线性光。两组相差 `MB_TRAIL_ALPHA` 一项。`d3dx9_43` 主效果分别约 2.44／2.49 秒，默认约 1.06 秒。线性光转换的幂函数输入明确为非负值，组合配置编译无对应警告。
- 1920×1080 和 3840×1728 用旧版 D3DX 实际执行速度场、分块和重建，验证组合下的第二方向、加法保护、已合成的半透明表面、近景遮挡、透明拖尾和切镜只用自身速度。默认关闭路径与上一提交逐像素一致。
- 用同一个 `ID3DXEffectPool` 创建主效果、模型和两份附件效果。实际读回确认相机历史与切镜速度纹理在这些效果之间共享，两份附件各自保存独立的矩阵纹理。模型效果在离屏编译副本中使用 `TEXCOORD7`。MME 内的效果池、`_INDEX`、自动映射和脚本顺序仍待实机验收。

同版本试用目录的 `Profiles` 下有三份配置。将需要的一份复制为试用目录的 `Settings.fxh`，再重载同一个 `AdvancedMotionBlur.x`。初始配置为 Scene。用 PMM 副本核对 `GeometryData` 指向同一试用目录，角色用 `MotionGeometry.fx`，需自身运动的 `.x` 附件用 `RigidMotion.fx`，仅用镜头速度的场景用 `DepthVelocity.fx`。

| 配置 | 用例 | 实机要看什么 |
|---|---|---|
| Baseline | `测试基线.pmm`，连续导出 500–900 | 30／60 fps 在相同镜头和快门下的拖影长度。另用 `MB_DEBUG=4` 检查不限帧和低帧率预览 |
| Scene | `测试基线_带场景.pmm`，`测试12.avi` 的 10.200 秒前后 | 右手旁栅栏拖影连续，前后遮挡和手部拖尾正确。需要定位时用同一配置单独切换 `MB_LAYERED_TRAIL` |
| Scene | `测试基线.pmm` 的 531、751、831 帧和连续运镜 | 硬切没有整屏拖影，运动角色保留自身拖影。单独检查控制器其他栏的 `Force Cut`、`Keep Camera` 及关键帧 |
| Scene | 固定镜头的两个移动 `.x` 附件，以及快速运动的细线或发梢 | 两个附件和各材质的拖尾方向正确。细线无明显断点，加法层和眼镜片观感可接受。亮暗边缘用 `MB_LINEAR_LIGHT` 单独对照 |
| RGBA | 隐藏不透明背景的同一小段 | 导出保留 Alpha，按预乘方式叠到黑底和白底后轮廓外拖尾可见 |

以上原生用例待用户实测。组合通过后再逐项记录默认开关验收结果。
